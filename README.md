# SPI Master-Slave Command Communication

This project demonstrates custom full-duplex SPI communication and handshake protocol between an **STM32 Discovery board (Master)** and an **Arduino/Microcontroller (Slave)**, verified using a USB Logic Analyzer and Saleae Logic 2 software.

---

## Hardware Setup

* **Master Board:** STM32F407G-DISC1 Development Board
* **Slave Board:** Arduino / AVR Board
* **Debugging Tools:** 8-Channel 24MHz USB Logic Analyzer connected via breadboard jumper wires.
* **Connections:**
  * **MOSI:** Master Output $\rightarrow$ Slave Input
  * **MISO:** Master Input $\leftarrow$ Slave Output
  * **SCLK:** Serial Clock generated by STM32
  * **CS / Enable:** Chip Select pin driving active-low hardware/software slave management

---

## Logic Analyzer Capture & Signal Analysis

The logic analyzer captures full-duplex SPI transactions configured on SPI Channel 2:

* **Channel 0 (`D0`):** `SPI[2] - Clock`
* **Channel 1 (`D1`):** `SPI[2] - MOSI`
* **Channel 2 (`D2`):** `SPI[2] - MISO`
* **Channel 3 (`D3`):** `SPI[2] - Enable` (Chip Select)

---

## Communication Protocol & Data Analysis

### Protocol Sequence
1. **Command Transmission:** Master transmits a command byte (e.g., `CMD_LED_CTRL` = `0x50`) over MOSI.
2. **Handshake Verification:**
   * Slave returns its status byte over MISO (`0xF5` for `ACK`, `0xA5` for `NACK`).
   * Master sends dummy byte (`0xFF`) during clock cycles to read the slave's response.
3. **Payload / Arguments:** Once ACK (`0xF5`) is received, command arguments (Pin number and ON/OFF state) are transmitted in subsequent frames.

## Verification Summary
* Handshake verification was successful with the slave returning valid `ACK` (`0xF5`) bytes.
* Both full-duplex shift register byte swaps and Chip Select line toggles align with expected protocol timing (~3.875 µs byte transaction duration).
